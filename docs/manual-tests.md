# Manual clipboard and remote checks

These checks require a human-controlled system clipboard and are not claimed as completed by DataTransfer fixture tests. Use disposable folders and images. Record VS Code, extension, OS, clipboard source application, MDX language extension/version, local/remote transport, destination, exact inserted text, and file hashes before/after every action.

1. Install the VSIX and an MDX language extension. Create `docs/guide.mdx` and `docs/guide.md`. Confirm their status-bar languages remain MDX and Markdown.
2. Leave settings at defaults. Capture a screenshot to the clipboard using the OS screenshot UI. Paste with Cmd+V/Ctrl+V in MDX. Check the new file and image reference. Undo once: both disappear. Redo once: the same path and identical bytes return. Repeat in Markdown as a native baseline.
3. Apply the README destination example. Capture a fresh screenshot and paste in MDX. Verify the image is in `docs/guide/`. Compare native Markdown using a separate folder with the same document basename. Native defaults use `alt text` and no leading `./`.
4. Copy PNG, JPEG, GIF, and WebP files from Finder/Explorer/a Linux file manager outside the workspace. Test each individually, then select several files and copy/paste together. Record which MIME entries the OS/VS Code actually exposes if any input cannot be pasted. Confirm every new image has the expected bytes.
5. Repeat with files inside either workspace folder. They must be referenced in place; undo must not delete them. Test a URI containing spaces, Chinese characters, parentheses, `#`, and `%`. Inspect rendering in your MDX toolchain as well as the exact native Markdown baseline; native paths are not comprehensively URL-encoded.
6. With `nameIncrementally`, paste a conflicting filename twice. Undo twice, then redo twice. Check `name.png` / `name-1.png`, text order, and hashes at every step. Paste, type a normal sentence, undo twice, redo twice. After another undo, paste different bytes and verify the abandoned redo branch does not return.
7. Repeat the collision tests with `overwrite`, including the README destination example. With known bytes already at `guide/screenshot.png`, paste must create `guide/screenshot-1.png`, insert its reference, and show no collision warning. Undo removes only the new file and reference; Redo restores the same path and bytes. Confirm the original image remains unchanged throughout. Pre-create `screenshot-1.png` and repeat: the next paste must use `screenshot-2.png`. Both Markdown overwrite settings intentionally use incremental naming in MDX.
8. Paste plain text, a copied URL, an HTML fragment, and unsupported image data. Confirm the provider does not replace ordinary paste. Verify ordinary `.md` documents still use native Markdown and another MDX extension's language features remain available.
9. Paste in an unsaved MDX document, with file pasting disabled, with copying disabled, and into a read-only folder. Confirm safe fallback/warnings and no unexpected image files. Test a destination with an existing non-directory parent and a symlink outside the root.
10. Repeat steps 2–6 with a two-root workspace and through Remote SSH, WSL, and Dev Containers as available. Keep the extension installed on the workspace side. Check URI authority, destination root, relative links, and filesystem permissions. Record unavailable environments as untested.
11. In a disposable test folder only, change a newly pasted file externally before Undo and before Redo. Record native confirmation prompts, bytes, and whether the file is removed. Do not expect the extension to override VS Code's handling of outside changes.
12. Exercise two rapid pastes and a failing remote connection during a multi-image paste. Native file edits are not rollback-atomic. If a remote write fails after an earlier file succeeds, inspect and remove any unreferenced partial file. Record the result; do not report this as full transactional rollback.

Release evidence should distinguish automated results, manually verified results, and untested combinations. No OS screenshot or remote transport test is implicitly marked passed by CI.
